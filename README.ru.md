# Codex Telegram Bridge

[English](README.md) · [Русский](README.ru.md)

Управляйте локальными чатами приложения Codex через Telegram-бота: получайте готовые результаты и ошибки, выбирайте нужный чат и отправляйте в него текст, изображения или голосовые сообщения с телефона.

Это независимый проект сообщества, а не официальная интеграция OpenAI или Telegram. Мост использует внутренний IPC-протокол Codex для Windows и локальную базу чатов. Обновление Codex может потребовать адаптации моста.

## Возможности

- **Один чат или все чаты.** Выберите чат для обычных сообщений или получайте результаты из всех чатов и отвечайте на конкретное уведомление.
- **Тихие уведомления.** Бот присылает результаты и ошибки без промежуточного хода работы и обычных подтверждений доставки.
- **Текст, фотографии и голосовые.** Голос распознаётся локально через faster-whisper, затем текст передаётся в Codex.
- **Продолжение работы.** Сообщение запускает новый ход в свободном чате или дополняет выполняющуюся задачу через её владельца в приложении.
- **Сохранение состояния.** SQLite хранит очереди и маршруты. При неопределённом результате доставки бот предлагает проверить чат вместо автоматической повторной отправки задания.
- **Явный список пользователей.** Только личные Telegram-чаты владельца и добавленных им пользователей.
- **Два транспорта.** Прямой опрос Telegram или дополнительный HTTPS-релей на PHP/MySQL с webhook и быстрым меню чатов.

Интерфейс бота сейчас на русском языке. Документация доступна на русском и английском.

## Схема работы

```text
Telegram-бот <-> Мост на Windows <-> IPC приложения Codex
                       |
                 локальная SQLite
                       |
               локальный Whisper

Дополнительный серверный транспорт:
Telegram webhook -> PHP/MySQL-релей <- опрос мостом по HTTPS
```

Компьютер и Codex должны работать. Релей может хранить входящие сообщения, пока компьютер выключен, но сам Codex не запускает. Результаты и вложения передаются через Telegram Bot API. Открывать входящий порт на компьютере не требуется.

## Требования

- Windows и запущенное приложение Codex с выполненным входом под той же учётной записью Windows.
- Node.js **22.13 или новее** с `node:sqlite`; локальные проверки выполнены на Node.js 22.19.
- Windows PowerShell 5.1 для защиты секретов через DPAPI — входит в Windows.
- Токен бота от [BotFather](https://t.me/BotFather) и ваш числовой Telegram ID.
- Для голоса: Python 3.10+, зависимости из `speech/requirements.txt` и локальная модель faster-whisper.
- Для релея: PHP 8.1+, PDO MySQL, cURL, mbstring, MySQL/MariaDB и хостинг с HTTPS.

npm-зависимостей нет. Версия рассчитана на схему локальной базы `state_5.sqlite` и версию потока IPC 11. Другие ОС, облачные чаты и будущие версии IPC этим выпуском не поддерживаются.

## Быстрый запуск: прямой опрос Telegram

1. Склонируйте проект и откройте PowerShell в его каталоге:

   ```powershell
   git clone https://github.com/belvision/codex-telegram-bridge.git
   cd codex-telegram-bridge
   ```

2. Используйте отдельного бота без webhook и других процессов опроса. Укажите **свой** числовой Telegram ID:

   ```powershell
   powershell.exe -NoProfile -File .\scripts\setup.ps1 -OwnerUserId 123456789
   ```

   Число в примере — заглушка. Скрипт запросит токен скрытым вводом, зашифрует его через Windows DPAPI и сохранит настройки в `%LOCALAPPDATA%\CodexTelegramBridge`. Существующую конфигурацию он не перезаписывает.

3. Откройте нужные чаты в Codex и запустите мост:

   ```powershell
   npm start
   ```

4. Отправьте боту `/start`, нажмите **Один чат** и выберите нужный чат либо включите **Все чаты**.

Для работы без окна выполните `wscript.exe desktop\start-hidden.vbs`. Скрипт ищет Node.js в стандартной папке Program Files или `C:\nvm4w\nodejs`; при другом расположении измените путь в скрипте. После выхода процесс перезапускается через 30 секунд. Для полной остановки завершите и launcher, и дочерний процесс Node. Не запускайте несколько копий для одного бота.

## Команды и маршрутизация

| Команда | Действие |
| --- | --- |
| `/start`, `/mode` | Выбор одного чата или всех чатов |
| `/chat` | Список чатов |
| `/status` | Состояние подключения и очередей |

В режиме одного чата обычные сообщения, изображения и голосовые отправляются в выбранный чат. В режиме всех чатов используйте Telegram «Ответить» на уведомление или кнопку **Ответить**. Кнопка **Только этот чат** включает режим выбранного чата. В режиме одного чата ответ на старое уведомление также направляется в текущий выбранный чат.

Подтверждения доступа автоматически не выдаются. Эта версия пересылает только итоговые результаты и ошибки: запросы разрешений и другие блокирующие вопросы нужно отслеживать в приложении. Текст в выбранном чате может ответить на его ожидающую структурированную форму. Старая история при первом сканировании не рассылается.

## Личные настройки

Структура настроек приведена в `desktop/config.example.json`. Настоящие `config.json`, DPAPI-файлы, `bridge.sqlite`, вложения, журналы и `status.json` должны находиться в личной папке вне репозитория.

- `ownerUserId` и `ownerChatId`: ваш числовой Telegram ID, одинаковый в обоих полях.
- `additionalUsers`: массив дополнительных числовых ID. Каждый пользователь получает доступ к общему списку локальных чатов и может управлять ими; отдельной изоляции пользователей нет.
- `relayUrl`: пустая строка для прямого опроса либо HTTPS-адрес `telegram-relay.php`.
- `voiceLanguage`: язык распознавания, по умолчанию `ru`.
- `whisperRoot`: необязательный абсолютный путь к Python-окружению, обработчику и модели; по умолчанию используется папка `speech` проекта.
- `initialUpdateOffset`: обычно `0`, используется до появления сохранённого смещения опроса.

Для другой личной папки задайте `CODEX_TELEGRAM_HOME` и передайте тот же путь скрипту установки через `-PrivateDirectory`. При поиске базы чатов учитывается `CODEX_HOME`. Расшифровать DPAPI-файлы может только создавшая их учётная запись Windows.

## Локальное распознавание голоса

Выполните из каталога проекта:

```powershell
python -m venv speech\.venv
speech\.venv\Scripts\python.exe -m pip install -r speech\requirements.txt
speech\.venv\Scripts\python.exe -c "from huggingface_hub import snapshot_download; snapshot_download('mobiuslabsgmbh/faster-whisper-large-v3-turbo', local_dir='speech/models/turbo')"
```

Установка модели требует интернета и свободного места. Затем распознавание работает локально на CPU без сетевой загрузки моделей. Ограничения реализации: 20 МиБ и 10 минут на запись. Текст распознавания передаётся в Codex, а исходное голосовое проходит через Telegram. Без модели и окружения работают текст и изображения; для голоса будет сообщение об ошибке. Модели и окружение не включены в репозиторий и распространяются по лицензиям их авторов.

## Необязательный HTTPS-релей

Серверная часть выделена из исходной установки в самостоятельный проект. Внутренние имена `BookRelay`, `BookTelegram` и заголовок `X-Book-Relay-Key` оставлены для совместимости; приложение книги не требуется.

1. Загрузите `server/` на хостинг. Корнем сайта должна быть **только папка `server/public`**. `core/`, `bin/`, SQL и настройки не должны быть доступны по HTTP. Отключите вывод PHP-ошибок посетителям.
2. Создайте отдельную базу MySQL с пользователем и импортируйте `server/schema.sql`.
3. Создайте личную папку вне корня сайта. Задайте её абсолютный путь в `CODEX_TELEGRAM_PRIVATE_DIR` для PHP-запросов и команд CLI.
4. Скопируйте туда `server/config.example.php` под именем `config.php`. Укажите доступ к базе, токен бота, ID бота (число перед двоеточием в токене), ID владельца, публичный URL webhook и случайный ключ релея. Ключ релея и секрет webhook создайте независимо криптографическим генератором, например `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`.
5. Отдельный 64-символьный hex-секрет webhook сохраните в личном файле `webhook-secret`. Разрешите запись в личную папку учётной записи PHP для каталога чатов и файла блокировки; ограничьте остальных пользователей. Дополнительные ID при необходимости поместите массивом в `allowed-users.json` и продублируйте в настройках моста.
6. Запустите установку Windows с параметром `-RelayUrl https://example.com/telegram-relay.php`, указав тот же токен и ключ релея. Для уже установленного моста отредактируйте личный `config.json` и сохраните ключ через `Read-Host -AsSecureString | ConvertFrom-SecureString | Set-Content -Encoding ASCII` в личный файл `book-relay-key.dpapi`.
7. На сервере включите и проверьте webhook:

   ```sh
   php server/bin/codex-webhook-control.php enable
   php server/bin/codex-webhook-control.php status
   ```

8. Запустите мост. Он опубликует каталог чатов и будет опрашивать релей примерно раз в пять секунд в состоянии ожидания. `/start` и навигация по списку чатов могут отвечать непосредственно с сервера.

Скрипт управления также принимает `disable` — удаление webhook без сброса ожидающих обновлений Telegram — и `commands` для просмотра меню. Перед переходом с релея на прямой опрос остановите мост, проверьте и обработайте очереди, отключите webhook. Не используйте оба транспорта одновременно для одного бота.

## Приватность, ограничения и проверки

В репозитории только исходники и примеры настроек. Пароли, токены, личные ID, история чатов, базы и вложения исключены. Храните их вне каталога проекта даже при наличии `.gitignore`. Подробнее: [SECURITY.md](SECURITY.md).

Рабочие уведомления могут содержать личную информацию из чатов. Встроенный фильтр скрывает распространённые токены ботов и bearer-заголовки, но не гарантирует очистку любых секретов. Доступ следует выдавать только доверенным людям: их инструкции выполняются с разрешениями соответствующего чата Codex.

При несовпадении версии потока IPC отправка заданий приостанавливается до проверки совместимости. Если сообщение адресовано выгруженному чату, мост запрашивает его состояние и при отсутствии владельца автоматически открывает этот чат по ссылке Codex. Приложение при этом может переключиться на нужный чат. Отправка ждёт получения состояния; ссылка не содержит текста задания, отдельный app-server не запускается. Повторное пробуждение ограничено одним разом в минуту для каждого чата. Codex должен работать, а обработчик его ссылок в Windows — быть зарегистрирован. Статус доставки `unknown` требует ручной проверки; строго однократная доставка при сетевых сбоях не гарантируется.

Проверки без подключения рабочего бота:

```powershell
npm test
Get-ChildItem desktop\*.mjs | ForEach-Object { node --check $_.FullName }
Get-ChildItem server -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
```

Тесты проверяют разрешённых пользователей, очередь голоса на новой базе, восстановление после перезапуска, порядок сообщений внутри чата, опасные пути вложений, настройки HTTPS и обработку итогового ответа. Они не заменяют сквозную проверку с вашим ботом, версией Codex и хостингом.
